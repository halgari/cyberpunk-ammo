# v1 slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Common and Uncommon ammo for 9mm (Lexington), 5mm light rail (Omaha) and 10mm smart
(Yukimura), with an Ammo section on the weapon screen, ammo icons on selectors, NPCs carrying the
Uncommon, vendors selling the split, and container ammo converted into it.

**Architecture:** Records stay in TweakXL YAML, one file per caliber. Generic logic stays in
redscript: a new `AmmoDistribution` class decides which caliber and tier a vanilla ammo stack
becomes, and the vendor, container and NPC hooks call it. The weapon screen gets a third section
by wrapping `InventoryWeaponItemChooser`.

**Tech Stack:** Cyberpunk 2077 2.50, redscript, TweakXL, Codeware (localization, ink), CET (test
harness), the existing RED4ext plugin (unchanged).

**Spec:** `docs/superpowers/specs/2026-10-27-v1-slice-design.md`

## Global Constraints

- Game 2.50 (exe 3.0.88.46235). Windows tools on GE-Proton only, never system wine, never the
  game's prefix (`tools/linux/common.sh`).
- Don't commit unless the user asks. Don't restart the game or draw a weapon while the user is
  playing unless they agreed; full restarts for test rounds are agreed.
- Synthetic input doesn't reach the game: anything needing real firing, aiming or menus is a
  manual step for the user, listed in the task.
- Search game scripts in `reference/scripts`.
- Item text: names and descriptions exactly as in the spec's "Names and descriptions" table; any
  new text follows the voice rule there (plain, gun-counter slang, no made-up lore).
- Starting numbers from the spec: hollow point `DamagePerHit` ×1.2 and `CanWeaponIgnoreArmor`
  −0.5; sabot `ChargeTime` ×0.7 and `DamagePerHit` ×0.95; dumbfire `DamagePerHit` ×1.25 and no
  homing. Weights 9mm 0.06, 5mm 0.04, 10mm 0.08.
- Shares: Power 0.85/0.15, Tech 0.75/0.25, Smart 0.90/0.10. Loot weights 9mm 0.6, Tech_Light
  0.25, Smart_10 0.15. Owned bias 0.6. Uncommon only at `WeaponVendor` vendors.

## How every task is tested

There's no unit test framework; tests are CET Lua snippets run in the game.

- The loop: write the check snippet first; `tools/linux/cet.sh -f <snippet>` and see it fail (or
  see the record or function missing); implement; `tools/linux/deploy.sh` (runs the offline
  compile check, refuses to deploy on failure); `tools/linux/restart-game.sh`; run the snippet
  again and see it pass.
- Each snippet prints one `PASS <name>` or `FAIL <name>: <why>` line per assertion and lives in
  `tools/snippets/slice/`. A task is done when all its lines print PASS and its manual checks (if
  any) are confirmed by the user.
- Debug entry points for snippets live on `AmmoFeedSystem` (reached with
  `Game.GetScriptableSystemsContainer():Get("AmmoOverhaul.AmmoFeedSystem")`), because CET reaches
  scriptable systems reliably and module classes less so.

## Review Focus

1. **Existing saves with test items:** a save holding `Ammo.AO_9mm_Incendiary`,
   `Ammo.AO_9mm_TestDragon` or a fitted test selector must load without errors once those records
   are gone; the gun falls back to its default ammo. Pinned in Task 1 (load the dev save, which
   has them).
2. **The vanilla 9mm stack in a split:** `Ammo.HandgunAmmo` is both a vanilla item to convert and
   our 9mm Ball. Vendor restock and container conversion must not re-split 9mm Ball that was
   already the result of a split. Pinned in Tasks 6 and 7.
3. **Vending machines and non-gun vendors:** they must never get Uncommon rounds. Pinned in Task 6.
4. **Feed slot with no selector, on the new screen section:** an empty slot must still be
   clickable and list only that caliber's selectors. Pinned in Task 4.
5. **NPC Uncommon on a gun with a fixed preset:** the roll must skip a gun whose feed slot is
   already filled (e.g. the test gangers), not stack a second selector. Pinned in Task 5.

### Task 6: Distribution and vendors

**Files:**
- Create: `src/scripts/AmmoOverhaul/AmmoDistribution.reds`, `Vendors.reds`,
  `tools/snippets/slice/vendors.lua`
- Modify: `AmmoFeedSystem.reds` (debug entries), `docs/DESIGN.md` (new "Distribution" section)

**Interfaces:**
- Consumes: Task 1 AOData readers.
- Produces:
  - `public struct AOStack { let ammo: TweakDBID; let quantity: Int32; }`
  - `AmmoDistribution.Calibers(vanilla: TweakDBID) -> array<String>`: calibers whose
    `vanillaAmmo` is `vanilla`.
  - `AmmoDistribution.OwnedCalibers(player: ref<PlayerPuppet>) -> array<String>`: calibers of
    every weapon in the player's inventory.
  - `AmmoDistribution.Pick(vanilla: TweakDBID, maxTier: Int32, owned: array<String>) ->
    TweakDBID`: one target item. Caliber: with probability `OwnedBias()` a uniform pick among
    owned calibers of `vanilla` (if any), else a pick weighted by `LootWeight`. Tier: weighted by
    `TierShare(family, t)` for `t ≤ maxTier`. Returns `AmmoForTier(caliber, tier)`.
  - `AmmoDistribution.Spread(vanilla: TweakDBID, quantity: Int32, maxTier: Int32) ->
    array<AOStack>`: proportional split by `LootWeight` × `TierShare` (no owned bias), rounding
    down, remainder to the largest share; stacks of 0 left out; total equals `quantity`.
  - `AmmoFeedSystem.DebugSpread(vanilla: String, quantity: Int32, maxTier: Int32) -> String` and
    `DebugPick(vanilla: String, maxTier: Int32, n: Int32) -> String` (counts per item over `n`
    picks, using the real player's owned calibers).
  - `Vendors.reds`: `@wrapMethod(Vendor) InitializeStock()` and `RegenerateStock()`: after the
    original, rewrite `m_stock`: each stack whose item is `vanilla` for any caliber is replaced
    by `Spread(vanilla, quantity, maxTier)` where `maxTier` is 1 for
    `gamedataVendorType.WeaponVendor` and 0 otherwise; vending machines are left out by vanilla
    (`FillVendorInventory`) but get `maxTier` 0 if they ever reach here. Each new stack is built
    like vanilla stacks (`SItemStack` with `itemID = ItemID.FromTDBID(ammo)`, `quantity`, other
    fields copied from the replaced stack). Our new items are tagged `Ammo`, so
    `AlwaysInStock` restocks them.
